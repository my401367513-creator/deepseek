# 短剧技能：资产需求分析（Asset Library）

流水线第二环：**人物/剧本 → 资产拆解 → 资产卡 → 分镜引用**。
上游：`short-drama-script-analysis` 产出的人物档案（角色资产来源）；下游：`short-drama-prompts` 复用资产固定描述词。让同一资产在多个镜头中保持一致，是防漂移的根本手段。

## 1. 资产分类框架

资产按类型建卡，统一入 `assets.md` 管理：

| 分类 | 说明 | 来源/去向 |
|---|---|---|
| **人物资产** | 角色形象（引用 characters.md 的 canonical 描述词 + 声线/台词风格） | 人物分析技能 |
| **场景资产** | 固定地点（如老宅客厅、豪车后座） | 美术方向 |
| **道具资产** | 关键道具（手机、手镯、信物） | 美术方向 |
| **音频资产** | BGM / 音效 / 环境音 / 配音（见 2.2 音频资产卡） | 声音设计 |
| 服装资产 | 角色造型（常服/特定场景服装，可选扩展） | 人物分析技能 |
| 风格资产 | 光影/色调/材质（如冷暖对比光，可选扩展） | 全片统一 |

> 核心四类 = 人物 / 场景 / 道具 / 音频；服装与风格视项目需要作为扩展分类。

## 2. 资产卡标准（assets.md 条目）

```markdown
## <资产名>（类型：场景/道具/服装/风格）
- 标签：<题材/年代/情绪/复用场景，如：都市、民国、悬疑、暗调>
- 固定描述词：<供 Seedance 复用的 30–60 字>
- 参考图/首帧建议：<有/无>
- 复用场景：<哪些镜头/剧集可复用>
- 关联：<关联角色/项目>
```

**固定描述词规则**：30–60 字；分镜与提示词用固定命名引用（如 `资产:老宅客厅`），避免同一物体每次重新描述导致漂移。

### 2.2 音频资产卡（assets.md 条目）

```markdown
## <音频名>（类型：音频 · <BGM/音效/环境音/配音>）
- 标签：<情绪/用途，如：钩子、紧张、环境底噪>
- 用途与情绪：<在哪用、营造什么情绪>
- 对应镜头：<镜号，可多个>
- 制作方式：<AI 生成（音效/TTS）/版权素材库/后期合成>
- 声音要点：<音色/节奏/强度/情绪词，如「低频沉闷重音、逐次加重」>
- 关联：<关联角色/项目>
```

音频资产要点：短剧声音设计 = 钩子音效（前 3 秒）+ 环境底噪（场景真实感）+ 关键音效（爽点/反转卡点）；BGM 分段（情绪曲线）仅作为可选设计参考。**默认无 BGM（全局偏好）：全片无背景音乐，仅环境音/音效/台词配音；仅当原剧本明确要求时才建立 BGM 资产。** 音频资产在提示词阶段附到对应镜头，或交付后期/素材清单。

## 3. 建库流程

1. 剧本分析后先产出「资产清单」草稿（人物清单 + 场景/道具/服装/风格）
2. 与用户确认关键外观设定（或用户提供参考图），再落库；未确认项标注「待确认」
3. 分镜表引用资产名（如「镜 5：老宅客厅 资产 · 女主角 canonical 描述词」），保证镜头间一致
4. 每次成片后回填「实际效果」到资产卡与 `lessons.md`（什么设置出片成功率高）

## 4. 一致性策略

- 资产卡建好后全片复用固定命名，同一物体不重复描述
- 风格资产（光影/色调）跨镜头复用，保持全片视觉统一
- 关键资产（主角常驻场景、高复用道具）建议出参考图/首帧

### 4.1 剧情红线（全流程约束，用户要求）

- 资产设计（场景/道具/服装/音频）**只服务剧情呈现**，不得新增、删改、扩展剧情内容。
- 资产卡的「复用场景」「关联」以原剧本情节为准；不因资产设计需要而调整剧本。
- **所有会更改剧本的行为一律不采用**（集数/分集剧情/台词/情节/人物设定/时间线均以原剧本为准）。

## 5. 记忆库读写（本技能负责）

- **记忆根解析**（每次会话检查一次）：环境变量 `SHORT_DRAMA_MEMORY` 非空且路径存在 → 用之；否则默认 `{{cwd}}/short-drama-memory/`。云端同步与复刻协议见记忆根内 `REPLICATE.md`。
- **会话开始**：先读 `MEMORY.md` 恢复上下文；能判断项目时再读 `projects/<项目名>.md`。
- **本技能负责写入**：`assets.md`（新增/修订资产卡）；`projects/<项目名>.md` 的资产部分；成片后把「实际效果」回填到资产卡与 `lessons.md`。
- **用户纠正**：立即记入 `lessons.md` 与 `MEMORY.md` 偏好区，并在后续输出中遵守。
- **纪律**：只记录事实与用户确认的偏好，绝不编造；文件不存在用 `write` 创建，存在用 `edit` 增量更新。

## 6. 交付格式（用户要求，全流程通用）

- **所有反馈内容一律 text 模式**：用 ```text 代码块输出纯文本，不用 Markdown 富排版（表格/加粗/链接），方便直接复制。
- **交付文件用纯 text 格式**：扩展名 `.txt`，纯文本分隔线/编号，无 Markdown 富语法。

## 7. 全流程共用约束（跨技能）

- 镜头参数词典、环境与人物分离、同步环境规则、动作描述原则等**镜头描写规范以 `short-drama-prompts` 技能 2.7 为准**（本技能与 script-analysis 共用，不在本技能重复承载）。
