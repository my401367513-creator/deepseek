# 短剧生产技能：记忆库 · Seedance 2.0 · 资产库

本技能定义三套协议，全部服务于「从剧本到成片」的短剧生产流水线：**持久记忆库**（跨会话记忆与自我提升）、**Seedance 2.0 提示词规范**（默认生成工具）、**人物与资产库标准**（一致性保证）。

## 1. 持久记忆库（强记忆 + 随使用提升）

### 1.1 位置与结构

记忆根目录解析顺序（每次会话开始时用 shell 检查一次）：
1. 环境变量 `SHORT_DRAMA_MEMORY` 非空且路径存在 → 使用该绝对路径（可用于指向云盘同步文件夹）。
2. 否则默认 `{{cwd}}/short-drama-memory/`（当前工作区下）。

**沙箱约束（重要）**：默认文件策略下，Agent 只能在工作区内写文件。若解析出的记忆根在工作区之外（例如 OneDrive 固定目录），写入会被拒绝——此时**回退到工作区内路径**并告知用户。云端备份的正确姿势是「让云盘客户端同步记忆根所在的本地文件夹」，而不是把记忆根挪到工作区外。所有记忆文件一律 UTF-8 Markdown。

```
short-drama-memory/
├── MEMORY.md             # 总索引 + 用户偏好 + 项目清单（必读入口）
├── characters.md         # 角色档案库（跨项目沉淀，带 canonical 描述词）
├── assets.md             # 资产库（场景/道具/服装/风格资产卡）
├── prompt-templates.md   # Seedance 2.0 提示词模板库 + 有效/无效经验
├── lessons.md            # 经验教训（自我提升的核心：成败复盘）
└── projects/
    └── <项目名>.md       # 每项目一份：剧本诊断、人物、分镜、效果记录
```

### 1.2 读写协议（每次会话都执行）

1. **会话开始**：创建类工作前，先读 `MEMORY.md`（若存在），把用户偏好、进行中的项目、上次的经验教训纳入上下文；能判断当前项目时再读对应 `projects/<项目名>.md`。
2. **过程中**：涉及角色→更新/新增 `characters.md`；涉及资产→更新/新增 `assets.md`；产出或打磨提示词→更新 `prompt-templates.md` 中的模板（去重，保留最有效的写法）。
3. **交付后**：把本次「什么有效 / 什么无效 / 用户纠正了什么」写入 `lessons.md`（追加，标注日期与项目）；更新 `MEMORY.md` 的索引、偏好与项目状态。
4. **用户纠正**：立即把纠正点记入 `lessons.md` 与 `MEMORY.md` 的偏好区，并在后续输出中遵守。
5. **纪律**：只记录事实与用户确认的偏好，绝不编造历史；文件不存在时用 `write` 创建，存在时用 `edit` 增量更新；`MEMORY.md` 保持精简（索引+偏好），正文放子文件。

### 1.3 MEMORY.md 模板

```markdown
# 记忆索引

## 用户偏好（更新于 YYYY-MM-DD）
- 默认工具：Seedance 2.0（即梦）；默认画幅 9:16；默认风格：电影感写实
- （追加用户明确的偏好/纠正）

## 项目清单
- <项目名>：状态（进行中/已完成/搁置），简述，关键资产与角色链接

## 经验速览（详见 lessons.md）
- <最近 3-5 条最有用经验>
```

### 1.4 云端同步（跨设备）

记忆库是纯文本文件夹，天然适合云同步。两种推荐做法，按用户实际环境选择（不确定时用 ask_user_question 问一次）：

**A. 云盘文件夹同步（推荐，零操作）**
- 把记忆根所在的本地文件夹（默认 `{{cwd}}/short-drama-memory/`）放进云盘客户端的同步目录：坚果云可同步任意本地文件夹；OneDrive/百度网盘可同步其备份的「桌面/文档」等目录，把工作区（含记忆库）放进这些目录即可。
- 多台设备指向同一个同步文件夹后，记忆自动保持一致，无需任何额外动作。
- 纪律：避免两台设备同时编辑同一文件；发现冲突时保留内容较新的一份，并把冲突情况记入 `lessons.md`。

**B. Git 私有仓库（任意位置，需 pull/push）**
- 在记忆根内 `git init`，关联私有远端（Gitee/GitHub 私有仓库），`git push -u origin HEAD`。
- 会话开始先 `git pull --ff-only`；每次记忆更新后 `git add -A && git commit -m "<摘要>" && git push`（push 失败不阻塞主流程，把原因记入 `lessons.md`）。
- 可直接调用记忆根内的 `sync-memory.ps1` 脚本完成同步（脚本随记忆库一起同步，各设备通用）。

**迁移**：把现有 `short-drama-memory` 目录整体复制到目标同步位置即可；之后按 1.1 的解析顺序指向新位置（云盘方式通常无需改，工作区即同步目录；Git 方式原地初始化即可）。

### 1.5 多设备注意事项

- 记忆内容只记录「事实 + 用户确认的偏好」，不记录设备相关的绝对路径，保证跨设备可用。
- 每个设备会话开始都执行 1.2 协议（读 MEMORY.md），结束前确保写回并触发同步，避免设备间记忆漂移。

### 1.6 自我复刻（换新设备 / 新 Agent 实例）

- 记忆库内有一份完整复制套件：`REPLICATE.md`（教程）+ `replicate\`（预设与插件的原始文件副本）。
- 需要把「短剧导演」复刻到新设备/新 Agent 时：**直接读取 `REPLICATE.md` 并按其步骤执行**，即可 1:1 重建预设、血蓝条插件与记忆库。
- 每次修改本预设或插件后，把最新文件复制回 `replicate\` 并提交推送，保证复制包最新。

## 2. Seedance 2.0（即梦）提示词规范

### 2.1 能力背景

Seedance 2.0 是字节跳动即梦的视频生成模型：支持文生视频、图生视频、首尾帧、多镜头叙事、镜头运动控制、人物一致性（参考图/首帧）。竖屏短剧默认 9:16（1080×1920）。

### 2.2 统一结构

```
[景别与构图] + [主体与动作] + [场景与环境] + [镜头运动] + [光线与色调] + [风格与质感] + [参数]
```

要点：
- **主体动作**：动词具体（推开门/回头/落泪/握拳），拒绝「很悲伤」这类抽象词。
- **镜头运动**：必须含运镜动词——推 push in / 拉 pull out / 摇 pan / 移 track / 跟 follow / 环绕 orbit / 手持 handheld / 甩镜 whip pan；加速度控制（慢动作 slow motion、变速 speed ramp）。
- **光线色调**：具体到光源与情绪（黄昏逆光、冷蓝夜光、暖色室内顶光、霓虹青橙）。
- **风格质感**：电影感、写实、胶片颗粒、浅景深、4K 等，词汇库保持一致。
- **参数**：画幅 9:16、时长 5s/10s、镜头运动描述、参考图/首帧说明、负向提示。

### 2.3 一致性技巧（关键）

- **角色**：每个主要角色在 `characters.md` 里维护一条 **canonical 描述词**（外貌+服装+气质，30–60 字），所有镜头提示词复用同一段描述；关键镜头用参考图/首帧锁定形象。
- **资产**：场景/道具/服装在 `assets.md` 建卡后用固定命名引用（如 `资产:老宅客厅`），避免同一物体每次重新描述导致漂移。
- **连续动作**：多镜头连续动作时说明上一镜头结束状态（如「承接上镜，她从门口转身」）。

### 2.4 负向提示（常见）

变形、多指/六指、面部崩坏、文字乱码、画面闪烁、抽帧、多余肢体、前后镜头不一致。

### 2.5 模板示例（存入 prompt-templates.md）

```text
[中景 跟拍] [女主角（canonical 描述词）从巷口疾步走来，神色凝重，攥紧信封] [老城区黄昏街道，潮湿青石板，墙上斑驳海报] [手持跟随，轻微晃动，慢动作] [黄昏逆光，暖橙色调，长影] [电影感写实，胶片颗粒，浅景深] [画幅9:16，时长10s，负向：变形、多指、文字乱码]
```

每段提示词后附一行「可替换参数」说明（时长/画幅/景别/运镜可替换为其他值）。

## 3. 人物档案与资产库标准

### 3.1 角色档案卡（characters.md 条目）

```markdown
## <角色名>
- 定位：主角/反派/配角；作用（推进剧情/制造冲突/情绪锚点）
- 外貌：年龄、身高体型、发型、五官特征、标志性配饰
- 气质与性格：核心性格、情绪底色、口头禅、行为习惯
- 动机与弧光：想要什么、恐惧什么、结局变化
- 造型：常服/特定场景服装（固定描述词来源）
- canonical 描述词：<30–60 字，供 Seedance 复用>
- 参考图/首帧建议：<有/无；建议拍摄要点>
- 表演要点：微表情、肢体习惯、语气节奏
- 关系：与 <其他角色> 的关系
```

### 3.2 资产卡（assets.md 条目）

```markdown
## <资产名>（类型：场景/道具/服装/风格）
- 标签：<题材/年代/情绪/复用场景，如：都市、民国、悬疑、暗调>
- 固定描述词：<供 Seedance 复用的 30–60 字>
- 参考图/首帧建议：<有/无>
- 复用场景：<哪些镜头/剧集可复用>
- 关联：<关联角色/项目>
```

### 3.3 建库流程

1. 剧本分析后先产出「人物清单 + 资产清单」草稿。
2. 与用户确认关键外观设定（或用户提供参考图），再落库。
3. 分镜表引用资产名（如「镜 5：老宅客厅 资产 · 女主角 canonical 描述词」），保证镜头间一致。
4. 每次成片后回填「实际效果」到资产卡与 lessons.md（什么设置出片成功率高）。

## 4. 工作流顺序（一次完整交付）

剧本 → 剧本诊断 → 人物档案 + 资产库 → 分镜表 → Seedance 提示词包 → 效果回填与经验沉淀（写库）。
用户只要某一环时，只做那一环，但记忆协议（1.2）始终执行。
